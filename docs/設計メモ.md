# 設計メモ

作成日: 2026-09-09

## 1. 既存アプリの調査結果

### 1-1. 「3DデータをARで見よう」（kaihatuiinkai.jp/nesopuro2/artool/）

実装を読んだ結果、以下が判明した。

- 構成: **A-Frame 1.2.0 + AR.js（`aframe-ar-nft.js`）**、マーカー型（`marker/pattern-AR.patt`）
- 別バージョンとして MindAR 版（`../mindar/`）、顔認識版（`../mindar_face/`）、
  マーカーレス版（`../modelviewer/` = Google `<model-viewer>`）が存在する
- 端末別に4ページ（Windows/ChromeBook × イン/アウトカメラ、iPad × イン/アウトカメラ）
- GLB、**2MB以下**の制限
- サイト上の既知バグ表記:「Tinkercadで作成したglb図形が表示されない → 大きさを『100』にすると表示されます」

`3Dupload.html` の中核部分:

```js
myARData += "<a-marker id='idMarker' type='pattern' url='./marker/pattern-AR.patt'>";
myARData += "<a-entity id='idARmodel' gltf-model='#01_my3Dmame'";
myARData += " scale='"    + idScale     + " " + ... + "'";   // ← プルダウン値
myARData += " position='" + idPositionX + " " + ... + "'";   // ← プルダウン値
myARData += " rotation='" + idRotationX + " " + ... + "'";   // ← プルダウン値
myARData += "animation ='property :rotation;";               // ← 常時自動回転
```

**大きさ・位置・向きをすべて利用者が手動指定する設計**。これが不安定さの直接の原因。

### 1-2. 「作ってみよう！」（frproj.jp/WGL/Main.html）

- 構成: three.js（2014年頃の古い版）+ 独自CSG（`threecsg.js`）
- 書き出し形式: `.stl / .lgd / .obj / .png / .glb / .svg`（`downloadBoard.js`）
  - **GLB書き出しは可能**（`GLTFExporter.js`、2023-12-30版を後付けで搭載）
- **座標系は Z-up**。根拠 —
  ```js
  ckeckData: function(){ ... bounBox.min.z < -0.0001 && jAlert(ms.m_er_data, ...) }
  ```
  「モデルは z=0 平面より下に出てはいけない」という検証。つまり **Z が高さ**。
- 3Dプリンタ／木材加工向けツールであり、**単位は mm**。

## 2. 不具合の原因と対処

| 症状 | 原因 | 本アプリの対処 |
|---|---|---|
| 直立しない | Z-up（CAD）と Y-up（glTF規格・A-Frame）の不一致。three.js の `GLTFExporter` は軸変換をしないため、Z-upのまま書き出される | `detectUp()` で上方向を推定し、Z-upなら X軸まわりに −90° 回転 |
| 画面外に飛ぶ | 単位の不一致。CADの mm 値がそのまま入るため、200mm の作品が「200メートル」になる | 回転後のバウンディングボックスを再計測し、**最大辺 = マーカー1辺** になるよう一様スケール |
| 位置がずれる | 原点の取り方がCADごとに違う | 水平方向は中心を原点へ、垂直方向は底面を y=0（マーカー面）へ |
| ふらふら動く | `animation` による常時自動回転 | 既定で無効。「ゆっくり回す」を選んだときのみ有効 |
| ちらつく | マーカー姿勢の平滑化が無効 | `smooth / smoothCount / smoothTolerance / smoothThreshold` を有効化 |

### 上方向の推定ロジック（`detectUp`）

単純な「min が 0 なら接地」だけでは、両軸とも 0 のときに判別できない。
そこで 2つの手がかりを加点方式で組み合わせている。

```
その軸の min が 0 付近           … +2（その平面に接地している）
他方の軸の中心が 0 付近          … +1（そちらが水平面である）
```

- 「作ってみよう！」の作品: `min.z ≈ 0`（+2）かつ `center.y ≈ 0`（+1）→ **Z-up (3点)**
- Tinkercad 等の Y-up 出力: `min.y ≈ 0`（+2）かつ `center.z ≈ 0`（+1）→ **Y-up (3点)**

誤判定に備え、UI から `auto / z / y` を手動で切り替えられるようにしてある
（AR画面の「向きをかえる」ボタン、ホーム画面の「上の向き」）。

### 計測時の注意（`measureLocal`）

`THREE.Box3.setFromObject()` は**ワールド空間**のAABBを返す。
モデルはマーカーの子であり、マーカーの姿勢は毎フレーム変わるため、
そのまま使うと正規化の結果が毎フレーム変動してしまう。
一時的に単位行列のダミー親へ付け替えて計測している。

## 3. マテリアルの安全化（`prepareMaterials`）

「作ってみよう！」は CSG（`threecsg.js`）でブーリアン演算を行うため、
書き出されたジオメトリの法線が欠落・反転していることがある。

- 法線属性がなければ `computeVertexNormals()`
- `side = DoubleSide`（法線反転で面が消えるのを防ぐ）
- glTF既定の PBR は `metalness = 1` で、環境マップがないと**真っ黒**になる → 金属度を下げる
- ほぼ黒の色は灰色に置換（背景に溶けるのを防ぐ）

見た目のCAD完全再現は目標としない（ユーザー合意：2026-09-09）。陰影は簡易照明で足りる。

## 4. スクリーンショットの実現方式

**この機能があるため、マーカーレス（`<model-viewer>` → Scene Viewer / Quick Look）方式は採用できない。**
ARの描画がOSのネイティブアプリ側で行われるため、Web側から画像を取得できないため。

マーカー型（AR.js）は `getUserMedia` のカメラ映像を自前の `<video>` として保持しているので、
以下のように合成できる。

```
出力キャンバス ← ① video を object-fit:cover 相当で描画
              ← ② WebGLキャンバスを重ねて描画
              → toBlob('image/png')
```

必須条件: `renderer="preserveDrawingBuffer: true"`。
これがないと WebGL キャンバスの読み出しが黒く抜ける。

## 5. 外部依存の排除

AR.js の `preset="hiro"` は、内部で以下を**外部サイトから取得**する。

```
baseURL = "https://ar-js-org.github.io/AR.js/three.js/"
  → examples/marker-training/examples/pattern-files/pattern-hiro.patt
  → ../data/data/camera_para.dat
```

学校ネットワークで遮断されると無言で失敗するため、`preset` は使わず
同梱ファイルを明示指定している。

```js
marker.setAttribute('type', 'pattern');
marker.setAttribute('url', 'marker/pattern-hiro.patt');
scene.setAttribute('arjs', '... cameraParametersUrl: data/camera_para.dat ...');
```
